# qq-bridge-enhanced v1.1.0

在 v1.0.3 基础上的新功能版本：

- **定时任务**：按时区到点发消息，或者到点叫 AI 来说。
- **定时静默**：按时间段让 AI 停下来省 token。
- **切换 / 修改人格在二代仿真里真正生效**：以前要等会话重建，现在下一次唤醒或立即生效。
- **切到 agent 时可以带上私聊长期记忆**。

支持系统不变：**Windows、macOS、Linux**。逐条改动见 [CHANGELOG.md](../../CHANGELOG.md)。

## 新功能：定时任务

在桥接控制台「聊天行为 → 定时任务」里设置。说明见 [docs/guides/SCHEDULER.md](../guides/SCHEDULER.md)。

### 时间由谁算

- 时间由桥接的程序计算和执行，不靠 AI 记着。
- 按任务自己的时区算，出厂默认北京时间，与这台电脑的时区无关。
- 有夏令时的地区按当地墙上时间算。
- 时区下拉列出全部时区，每项带当前的 UTC 偏移，如「Asia/Shanghai（UTC+8，北京时间）」。

### 重复方式

- 一次性、每天、每周、工作日、每月几号、每月第几个周几、每年、特殊日期。
- 每隔 N 天、每隔 N 分钟。
- 每天随机几次、每月随机几次。
- 高级：cron 表达式。只能在控制台设置，AI 不能用。
- 都可以加开始 / 结束日期、排除日期、跳过法定节假日、共执行几次后停止。
- 表单实时预览接下来 5 次的具体时间。

### 内容

- **固定文字**：桥接直接发。
- **叫 AI 来说**：唤醒那个会话自己的 AI，各群的规则和上下文各自生效。

### 对象与入口

- 发送对象：管理员私聊、白名单好友、白名单群，可多选。
- 管理员也可以在私聊里用 `/remind`（桥接直接处理，不进模型），或者在二代仿真里直接跟 AI 说，让它用 `qq_schedule_*` 登记。

### 安全

- 总开关和限制只能由你在控制台或管理员命令里改，AI 改不了。
- AI 只能在管理员私聊里登记。默认只能发给管理员私聊；发往群的任务要先打开开关，并且登记后先暂停，等你确认。
- 有任务数、每天条数、每群条数、最小间隔这些上限。
- 「定时任务免打扰」时段：只拦定时任务发往群的消息，不影响 AI 平时被 @ 时回复。
- 新建、修改、删除都写进审计日志。

## 新功能：定时静默

在「运行总览 → 静默开关」里设置。说明见 [docs/guides/SILENCE.md](../guides/SILENCE.md)。

### 时间段

- 可以设多个时间段，每个带开关。
- 哪些天：每天 / 工作日 / 周末 / 自选，可以跳过法定节假日。
- 跨午夜的时间段以开始那天为准。
- 可以选时区。
- 「一键填入 DeepSeek 高峰时段」：北京时间工作日 09:00–12:00、14:00–18:00。

### 静默期间（默认）

- **停止一切唤醒**：以前的手动静默只拦发送，AI 仍被定时唤醒去思考，照样花钱。
- 群消息照样记进未读。
- 静默结束时，给被直接找过的会话补一次唤醒。
- 定时任务里「叫 AI 来说」的暂停（单个任务可以设成照常执行），固定文字照发。
- 管理员私聊默认不受影响，也可以勾选一起静默。

### 和手动开关的关系

- 手动开关优先。
- 定时静默期间点「恢复正常」，只临时恢复当前这一段，下一段照常。

## 修复：二代仿真里切换 / 修改人格不生效

### 原因

- 二代仿真的会话只在建立时读一次完整角色卡。之后每次唤醒只看到一行「当前角色：名字」。
- 所以在控制台切换人格、清除人格、改当前人格的内容之后，正在跑的群和私聊会话一直按旧卡说话，直到会话重建。看起来就像「切换失败」。

### 现在的做法

- 桥接按「会话 + 角色卡指纹」记下每个会话读到的是哪一版卡（只存指纹，不存内容）。
- 发现某个会话还没读到当前这一版时，下一次唤醒把新卡全文放在提示最前面，并说明旧卡作废。
- 记忆、群规则和会话本身都不动。

### 控制台选项

「切换当前启用的人格」和「编辑人格提示词 → 保存修改」下方都有生效方式：

- **下次唤醒时重新读卡**（默认）。
- **立即**：马上给还没读到新卡的会话各唤醒一次。
  - 这次唤醒 AI 不会专门发言，也不提换卡。
  - 已经读到新卡的会话自动跳过，两处都点也只读一次。
  - 定时静默中的会话，等静默结束后再读。

聊天模式 / 一代仿真每条消息都带角色卡，本来就立即生效，不受影响。

## 改进：切到 agent 时带上私聊长期记忆

- 切到 agent 时，除了最近的私聊往来，还可以把二代仿真里 AI 在管理员私聊记下的话题、想说的话、印象一起交接给 agent。
- 最多 1500 字，逐行脱敏，只取管理员私聊，不含任何群。
- 开关：「二代仿真 → 工具开关 → 切到 agent 时带上私聊长期记忆」，默认开。

## 从 v1.0.3 升级

1. 退出控制中心；备份 `config.json`、`state/`、`interface-platform/state/`。
2. 解压到新目录，把上面三样复制过去（如果有 `audio/`、自定义的 `roles/*.md`，也一起复制）。
3. 执行 `npm ci`，再跑 `npm run test:audit`。
   - macOS：删掉旧的「QQ Bridge 控制中心.app」，然后双击一次 `control-center.command`。
   - Linux：运行 `npm run linux-service -- --enable`。
4. **重启一次 DSH**：新的 `qq_schedule_*` 工具由 DSH 启动的 MCP 服务注册。preset 没有变化，不需要重跑 `setup-dsh.mjs`。
5. 启动控制中心，再启动接口平台和桥接。
   - 新的状态文件 `state/scheduler.json`、`state/silence-schedule.json`、`state/role-seen.json` 会自动创建。
   - 没有旧数据格式变化。
6. 升级后第一次唤醒，已有的二代会话会各收到一次当前角色卡，这是正常的。

## 测试

### 离线回归

- `npm run test:audit`：63 个离线回归脚本。发布包解压后从零 `npm ci` 验证：macOS 与 Linux（Docker `node:22-bookworm`）上都是 **62/63**。没过的 `test-console-encoding.mjs` 只在 Windows 上能通过。
- 接口平台：macOS 26 项全部通过；Linux 容器里 25 项通过、1 项跳过（「目录读不了」的用例在 root 下无法构造）。
- 新增：
  - `test-scheduler.mjs`：时区与夏令时、各种重复方式、cron、限额、免打扰、错过补发、AI 登记的权限。
  - `test-silence-schedule.mjs`：时间段、跨午夜、节假日、高峰预设、手动优先、静默期间不唤醒、结束补唤醒。
  - `test-role-refresh.mjs`：指纹与读卡记录、下次唤醒带新卡、立即唤醒只叫没读到的会话、保存与切换接口。
- `test-mode-handover.mjs` 新增 ⑥：带上私聊长期记忆。

### 真实环境（macOS + NapCat + DSH 桌面版 0.2.1-rc.2）

- **定时任务**：「每天随机 1 次，09:00～11:00（北京时间）」的任务在北京时间 10:48 触发，同时发往管理员私聊和一个群。
  - 群里 AI 发出 1 条。
  - 私聊当时正忙，排队到回合结束后补发，也发出 1 条。
- **人格生效**：切到新角色卡后，一个群在下一次被提问时读到新卡；另一个群和私聊在点「立即切换」约 8 秒后读到新卡，AI 没有为换卡发言。三个会话记下的是同一版卡。
