# qq-bridge-enhanced v1.1.2

在 v1.1.1 基础上的两项新功能：

- **按会话（群 / 私聊）分别设置人格卡**：A 群用傲娇助手、B 群用小鲸鱼、C 群不挂卡，都可以（来自 issue）。
- **断线期间错过的消息，恢复后补收**：电脑睡眠、NapCat 重启之后，AI 不会再「@ 了不回」。

支持系统不变：**Windows、macOS、Linux**。逐条改动见 [CHANGELOG.md](../../CHANGELOG.md)。

## 按会话设置人格卡

### 为什么

以前角色卡是全局单值：`state/current-role.json` 只存一个 `role`，所有群和私聊共用同一张卡；QQ 里的 `/role` 也是全局切换。

### 现在的做法

- `state/current-role.json` 增加可选的 `byKey`，按会话记：
  ```json
  { "role": "小鲸鱼", "mode": "active", "byKey": { "group:<群号>": "傲娇助手", "group:<群号>": null } }
  ```
  - 会话不在 `byKey` 里 → 用全局 `role`。**老状态文件原样可用，不用迁移**；没有单独设置时，写回去也还是老格式。
  - 值为 `null` → 这个会话不挂任何角色卡（不是回落到全局）。
  - 人格正文仍然只来自 `roles/<名字>.md`。手动静默仍是全局的。
- 控制台「人格与角色 → 按会话设置人格」：
  - 每个群 / 私聊选「跟随全局默认 / 不挂角色卡 / 某张卡」；还没聊过的会话可以直接填 `group:群号` 添加。
  - 引用的人格文件不存在时标红。
  - 有自己的一组生效方式：「下次唤醒时重新读卡」（默认）或「立即切换」；选「立即」只唤醒保存的那一个会话。
  - 进入页面、以及停在页面上时每 15 秒自动刷新；改了没保存的行标「未保存」，刷新时保留你的选择。
- **QQ 命令 `/role` 只对当前会话生效**（以前是全局）：
  - `/role 名字`：本会话换卡；`/role off`：本会话不挂卡；`/role default`：回到全局默认；`/role`：看本会话现在用哪张。
  - 全局人格只在控制台改。仍然只有管理员能用。
- 二代仿真的读卡刷新按会话算：给某个群换卡、或者改了某张卡的内容，只有用这张卡的会话会收到新卡，别的会话不会被唤醒。
  `qq_get_prompt`、唤醒提示里的【当前角色】、一代 / 聊天模式的角色提示也都按会话取。
- 人格改名时，单独用它的会话跟着改；人格被删时，单独用它的会话改成「不挂卡」，不会突然换成全局那张别的卡。

### 安全

- 全局 `role` 和 `byKey` 里的名字走同一条校验：清洗人格名，解析后的文件必须在 `roles/` 里（防 `../..` 之类的路径穿越）。
- 会话 key 只接受规范化的 `group:<正整数>` / `private:<正整数>`，别名（前导零）和非法 key 忽略。
- 新接口 `POST /api/roles/assign` 只开给控制台，AI 的令牌一律拒绝。AI 依然没有任何能改人格的工具。

## 断线补收

### 为什么

实测：Mac 合盖睡眠约 36 分钟，期间群里有人 @ 了 AI 两次。NapCat 醒来后没有把这些消息当作事件推给桥接，AI 一直不知道，看起来就是「@ 了不回」。
这些消息用 OneBot 的历史消息接口都能拉到。

### 现在的做法

- 桥接发现两次事件包隔了超过 2 分钟（心跳 30 秒一次），就在连接恢复 10 秒后，对当前模式允许的群和私聊各拉一次最近的历史消息。
- 断线这段时间错过的消息补收进未读：记原始发送时间、带 `backfill` 标记、按消息 ID 去重。有 @、私聊等直接找 AI 的照常排唤醒，
  唤醒提示最前面说明「这是断线期间错过、刚补收的」，AI 回复时不会假装是刚发的。
- 最后一次收到事件包的时间每分钟写进 `state/upstream-seen.json`，桥接自己停过 / 睡过也能发现断档。
- 拉历史失败（Mac 半睡半醒、NapCat 实例还没起来）时，记下这个会话最早还没补上的时间，一分钟后重试，最多 5 次；之后再断线恢复，也从更早的时间一起补。
- 超过 6 小时的消息只记下不唤醒；每个会话最多补 50 条；只在二代仿真里补（其它模式会逐条回复旧消息，只在活动记录里提醒）。
- 配置在 `snowluma.backfill`，见 [CONFIGURATION.md](../guides/CONFIGURATION.md)。

### 安全

- 补收的消息**不执行任何命令、审批、确认码、角色切换**（迟到的「确认」「/level L3」照样执行很危险）。
- 管理员私聊里补收到的命令，只私聊提醒你「没有执行，需要的话重发」，确认码打码。

### 补不回来的

拍一拍、入群等通知事件；断线期间被撤回的消息。

## 从 v1.1.1 升级

1. 退出控制中心；备份 `config.json`、`state/`、`interface-platform/state/`。
2. 解压到新目录，把上面三样复制过去（如果有 `audio/`、自定义的 `roles/*.md`，也一起复制）。
3. 执行 `npm ci`，再跑 `npm run test:audit`。
   - macOS：删掉旧的「QQ Bridge 控制中心.app」，然后双击一次 `control-center.command`。
   - Linux：运行 `npm run linux-service -- --enable`。
4. 启动控制中心，再启动接口平台和桥接。**不用重启 DSH**，也不用重跑 `setup-dsh.mjs`：preset 和 MCP 工具都没变。
5. **`/role` 的行为变了**：以前在任何地方发都是切全局人格，现在只改发命令的那个会话。全局人格在控制台「切换当前启用的人格」里改。
6. `off` / `clear` / `default` 成了保留名，不能再用作人格名。已经有同名人格的（极少见）请先改名。

新的状态文件 `state/upstream-seen.json` 会自动创建。新配置字段都有默认值；`state/current-role.json` 没有格式变化，原样可用。

## 测试

### 离线回归

- `npm run test:audit`：72 个离线回归脚本。发布包解压后从零 `npm ci` 验证：macOS 与 Linux（Docker `node:22-bookworm`）上都是 **71/72**。没过的 `test-console-encoding.mjs` 只在 Windows 上能通过。
- 新增：
  - `test-role-per-key.mjs`：老状态文件不变；命中 / 未命中 / `null` 三种回落；非法 key 与别名；路径穿越拒绝；改名、删除跟随；
    各会话注入自己的卡；只给卡变了的会话安排读卡唤醒（「立即」也只唤醒保存的那一个）；控制台接口 AI 调不了；`/role` 只改当前会话、群友发的不生效；控制台页面。
  - `test-backfill.mjs`：断档检测、去重、命令类识别、挑选规则；端到端补收、唤醒提示、不执行命令、太旧不唤醒、非二代不补；启动后自动触发；拉历史失败重试、从更早的时间补。

### 真实环境（macOS + NapCat 4.18.38 + DSH 桌面版 0.2.1-rc.2）

- 断线补收：合盖睡眠多次触发。一次补回一个群 12 条消息，其中 5 条命令类消息没有执行；AI 被唤醒后看过、判断不需要插话。
  另一次睡眠中途短暂唤醒时 NapCat 实例还没起来，拉历史全部失败——据此修了「失败也记成没有错过」的问题（加了重试，离线测试覆盖）。
- 按会话设置人格：控制台页面在真实桥接上读到 3 个会话、都跟随全局；升级后没有引发多余的读卡唤醒。
  给单个会话换卡的效果只做了离线测试，没有在真实群里实测。
