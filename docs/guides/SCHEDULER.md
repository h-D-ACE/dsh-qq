# 定时任务

按时区和规则到点发消息，或者到点叫 AI 来说。时间由**桥接的程序**负责计算和执行，不靠 AI 记着；
桥接没运行时错过的任务会按规则补发或跳过，并在启动时私聊告诉管理员。

代码在 `src/scheduler/`（`time.js` 时区、`schedule.js` 规则、`engine.js` 引擎、`commands.js` `/remind` 命令、`notes.js` 交给 AI 的说明），`bridge.js` 只负责接线。
数据存在 `state/scheduler.json`（0600，不进仓库）。

## 1. 在哪里用

| 入口 | 谁能用 | 能做什么 |
| --- | --- | --- |
| 桥接控制台「聊天行为 → 定时任务」 | 管理员 | 全部：总开关、时区、安全限制、新建 / 编辑 / 暂停 / 删除 / 试发、执行记录 |
| 管理员私聊 `/remind` | 管理员（ownerQQ） | 常用的新建、列出、删除、启用、暂停、试发；默认发给管理员自己的私聊。桥接直接处理，不交给模型 |
| 管理员私聊里跟 AI 说（二代仿真） | 管理员 | AI 用 `qq_schedule_create / list / update / delete` 登记；登记后桥接**另发一条确认**，附接下来几次的具体时间 |

`/remind` 用法（发 `/remind` 可以看）：

```
/remind list
/remind add daily 06:00 早上好
/remind add once 2026-10-22 09:00 交报告
/remind add in 30m 喝水                       （m 分钟 / h 小时 / d 天）
/remind add weekly 1,3,5 08:00 健身            （1=周一）
/remind add workdays 18:00 下班打卡
/remind add monthly 1,15,-1 20:00 交房租       （-1=每月最后一天）
/remind add random 3 09:00-22:00 ai 随便跟我聊一句
/remind del 3 · /remind on 3 · /remind off 3 · /remind run 3（立即试一次）
```

内容前加 `ai` = 叫 AI 来说；不加 = 固定文字。

## 2. 重复方式

| 方式 | 例子 | 说明 |
| --- | --- | --- |
| 一次性 | 2026-10-22 09:00 | |
| 每天 | 每天 06:00、22:00 | 可以多个时间 |
| 每周 | 周一、三、五 08:00 | |
| 工作日 | 工作日 18:00 | 周一至周五，去掉内置的法定节假日；**调休上班的周末不算**（内置表只有放假日） |
| 每月几号 | 每月 1 号、15 号、最后一天 20:00 | 当月没有 31 号时用最后一天 |
| 每月第几个周几 | 每月第 2 个周六 10:00；最后一个周五 | |
| 每年 | 每年 10-21 08:00 | 2 月 29 日只在闰年 |
| 特殊日期 | 2026-12-31 23:59；2027-01-01 00:00 | 最多 100 条 |
| 每隔 N 天 | 从 2026-10-20 起每 3 天 09:00 | |
| 每隔 N 分钟 | 08:00～23:00 之间每 240 分钟 | 至少 10 分钟 |
| 每天随机几次 | 每天 3 次，09:00～22:00，至少隔 60 分钟 | 时刻按「任务 + 日期」确定，重启不会重抽、不会多发 |
| 每月随机几次 | 每月 4 次，1～28 号，10:00～21:00 | 同上 |
| **高级：cron 表达式** | `0 9 * * 1-5`（工作日 9:00）；`*/30 9-18 * * *`；`@daily` | 5 段：分 时 日 月 周；周 0 和 7 都是周日，可写 `MON-FRI`；日和周都限定时按「任一满足」；一天最多触发 288 次。**只能在控制台设置**，AI 不能用（很容易写错，AI 用结构化规则就够了） |

所有方式都可以加：开始 / 结束日期、排除日期、跳过法定节假日、共执行几次后停止。
控制台的表单会**实时预览接下来 5 次**的具体时间，时区或时间段设错一眼就能看出来。

农历日期还没做（见 CHANGELOG 的后续计划）。

## 3. 内容：固定文字 / 叫 AI 来说

- **固定文字**：到点由桥接直接发。发给管理员时走管理通道专用发送，**任何模式下都能发**；发给群和其他好友时，当前模式不允许该会话（例如 agent 模式下群聊暂停）就跳过并记录。
- **叫 AI 来说**：到点唤醒**那个会话自己的 AI**（各群的规则、上下文各自生效，内容不会串到别的群），唤醒提示里带上「【定时任务】要你做的事」。
  二代仿真里走唤醒（就算唤醒原因在合并窗口里被升级成别的，任务说明也一样带上）；聊天模式和 agent 模式里直接交给当前会话。
  AI 的权限不变——只是多了一个唤醒原因。

## 4. 时区

- 默认时区在控制台设置，出厂是 `Asia/Shanghai`（北京时间）；每个任务也可以单独设（选「跟随默认时区」就用默认的）。
- 时区下拉列出浏览器认得的全部时区，每项后面带**当前的 UTC 偏移**，例如「Asia/Shanghai（UTC+8，北京时间）」；常用的排在最前，其余按偏移排序。有夏令时的地区（如美国、欧洲）偏移会随季节变，显示的是现在的偏移。
- 所有计算按任务时区进行，**与这台电脑的时区无关**（这台电脑在美国也一样按北京时间 06:00 发）。
- 列表、确认消息、执行记录都写明时区和 UTC 偏移，例如「2026-10-22 06:00（北京时间 UTC+8）」。

## 5. 安全限制（控制台可改，留空恢复默认）

| 限制 | 默认 | 说明 |
| --- | --- | --- |
| 同时任务上限 | 20 | |
| 单任务每天最多 | 12 次 | |
| 全部每天最多 | 50 条 | 按「发给一个对象」算一条 |
| 每个群每天最多 | 10 条 | 也降低 QQ 风控风险 |
| 单任务最多对象 | 10 个 | |
| 两次最小间隔 | 10 分钟 | 同一任务相邻两次 |
| 错过多久内补发 | 10 分钟 | 超过就跳过，记为「错过」；启动时私聊告诉管理员 |
| 固定时间随机偏移 | ±2 分钟 | 每天准点 06:00:00 太像机器人；可以设 0。随机类规则不加偏移 |
| 定时任务免打扰 | 00:00～07:00 | 时段内定时任务不往群里发（跳过这一次，不推迟）；发给私聊不受影响；手动试发不受限。**只管定时任务**，不影响 AI 平时被 @ 时回复；按默认时区计算 |
| 文字 / AI 说明最长 | 500 / 300 字 | 内容还会过敏感信息审计（路径、凭据） |

## 6. 安全边界

- **总开关和安全限制只能在控制台或管理员命令里改**，AI 改不了。
- **AI 只能在管理员私聊里登记**，默认只能发给管理员私聊；群里的会话调用会被拒绝（防止群友让机器人刷屏）。
- 开了「允许 AI 登记发往群 / 其他好友的任务」时，AI 登记的这类任务**先暂停**，要你在控制台打开或发 `/remind on 编号` 才生效。
- 发送对象只能是管理员私聊、白名单好友、白名单群，不能发给任意 QQ 号。
- AI 登记、修改、暂停、删除任务，桥接都会私聊告诉管理员；所有新建 / 修改 / 删除都写进管理审计日志。
- 工具说明要求 AI：**登记成功才能答应**，失败或没有这个工具时直接说做不到，不要口头答应。
- 为什么不用 DSH 自带的 `schedule_*` 工具：它们在 DSH 里起任务，绕过桥接的模式闸门和发送白名单，L2/L3 的工具守卫本来就拒绝它们。

## 7. 和「有限潜水」的关系

二代仿真里 AI 自己设的「睡到某时刻」（`qq_set_wake_config` 的 `sleepUntil`）保留，继续给 AI 管理自己的作息用（例如「十分钟后回来看看」）。
它每个会话只有一个时间点、被叫醒后容易被覆盖，**不适合当提醒用**；提醒请用定时任务。两者互不影响。
